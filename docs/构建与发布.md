# 构建与发布

## 源码组织

五个平台共用一套源码。`ui/web/` 是共享界面，`crates/notebook/` 是共享核心，`src-tauri/` 是统一原生入口。移动端原生工程由 GitHub 流水线根据配置生成，不在项目中长期维护两份独立界面。

项目锁定前端与 Rust 依赖。构建使用锁文件，避免同一版本源码在不同时间获取不同依赖。

## 本机允许执行的操作

本机可编辑全部代码、运行共享核心测试、构建共享网页资源、验证手机尺寸布局，并编译当前桌面平台。移动端原生编译、链接和安装包构建仅在 GitHub Actions 执行。

```bash
npm ci
npm test
npm run check
npm run build
cargo test --locked -p notebook-core
cargo fmt --all -- --check
cargo clippy --locked -p notebook-core --all-targets -- -D warnings
npm run test:e2e
npm run desktop:dev
```

在当前系统打包桌面应用：

```bash
npm run desktop:build
```

界面测试使用独立临时工作区。苹果桌面本机使用已安装的浏览器，云端验证使用安装的测试浏览器。

## 流水线

| 文件 | 执行条件 | 产物或结果 |
| --- | --- | --- |
| `.github/workflows/verify.yml` | 主分支更新、合并请求、手动触发 | 共享核心测试、静态检查、界面验证、截图与结果 |
| `.github/workflows/desktop.yml` | 版本标签、手动触发 | 苹果桌面应用、微软桌面安装包、Linux 安装包 |
| `.github/workflows/mobile.yml` | 版本标签、手动触发 | 安卓调试安装包、苹果移动端模拟器应用 |

安卓流程安装原生开发工具、生成工程，再针对主流六十四位架构生成调试安装包。苹果流程在苹果云端执行器安装目标工具链、生成工程，再构建不签名的模拟器应用并打包。

`mobile:android` 与 `mobile:ios` 构建脚本检查是否运行在 GitHub 流水线中。本机调用会直接退出，避免误执行移动端原生构建。不要绕过项目约定直接调用移动构建命令。

用户目前尚未提供源码远程仓库，项目不会自动创建或上传。等确定仓库后，将代码推送，再在操作页面手动执行对应流程。现阶段只能确认配置已写入、命令参数已核对；不能声称移动端云端构建已经通过。

## 真机与正式发布

安卓调试安装包用于测试，不等同于应用商店正式版本。正式发布需要稳定签名密钥、版本编号和签名构建流程。

苹果模拟器应用不能安装到真机。真机安装和应用商店发布需要苹果开发者团队、证书、描述文件以及对应签名设置。当前流水线没有这些私密资料，先提供模拟器构建。后续应在 GitHub 密钥配置中保存签名资料，再启用真机归档与安装包导出。

苹果桌面当前可构建本地应用。正式对外分发仍应进行开发者签名和公证。微软桌面正式分发也可以增加代码签名。上述发布资料不放入源码或笔记仓库。

## 移动端验收

云端构建成功后，仍需实机检查文件提供器的内容地址、中文输入法、键盘遮挡、应用切换恢复、安全区域、后台限制和私有仓库认证。浏览器窄屏测试不能替代安卓和苹果真机验证。

## 网页导入回归入口

共享验证流水线包含匿名网页压缩包的完整界面回归，检查字段类型与原色、父子目录折叠、记录打开、附件读取以及刷新后的层级。原始用户文件只在本机隔离工作区显式验证，不提交到源码或云端。

```bash
npm run test:e2e:notion-html
```

## 嵌套编辑器验证入口

共享界面验证流程增加折叠、嵌套、整组拖拽、就地菜单、键盘操作和保存保护回归。使用匿名数据和独立工作区，包含实际图片文件选择，手机只测试共享页面布局。

```bash
npm run test:e2e:editor
```

## 苹果桌面免费分发打包

在苹果桌面系统执行 `npm run desktop:build`，会构建应用，再自动进行临时签名、签名完整性校验和分发打包。构建端另需可用的Python 3，打包脚本只使用其标准库；接收方无需安装开发工具。

已有正式应用构建时，可以仅重新生成分发包：

```bash
npm run desktop:package:macos
```

默认生成：

- `artifacts/轻笺-苹果桌面.zip`：可直接转发，包含应用及「首次打开说明」。
- `artifacts/轻笺-苹果桌面.zip.sha256`：整个压缩包的校验摘要。
- `artifacts/首次打开说明.txt`：可单独发给接收方的中文说明。
- `artifacts/轻笺.app`：签名校验通过的应用副本。

打包先复制到临时目录，核对原字节、权限和符号链接，再对副本临时签名并执行严格完整性检查。压缩完成后重新核对全部条目、内容、中文路径编码和执行权限。任何检查失败都会停止出包，已有交付保持不变；通过后替换交付文件，旧文件保存在输出目录的 `.previous/` 下。分发文件和历史副本均不进入源码仓库。脚本不会修改用户安装的应用或笔记。

苹果云端桌面构建在原生编译后调用相同打包命令，只上传压缩包和校验摘要，避免直接上传应用目录时执行权限丢失。微软和其他桌面的安装包类型继续沿用原配置。底层 `npm run tauri -- build` 只负责原生构建；转发给别人前应使用上述分发打包入口。

「首次打开说明」位于压缩包顶层，用户解压后可直接双击阅读。首次启动被系统拦截时，说明引导先尝试打开，再进入「系统设置 → 隐私与安全性 → 仍要打开」，按提示确认；不要求使用终端命令或关闭整体安全保护。遇到损坏、恶意内容或管理策略限制时，说明引导联系发送者检查，而非一律放行。

临时签名不等于开发者身份认证或苹果公证，也不能消除首次打开提示。本机验证只证明打包和完整性检查通过，不代表已在另一台电脑或受管理设备上验收。当前没有远程源码仓库，更新后的云端流程尚未实际运行。

依据：[苹果首次打开指引](https://support.apple.com/zh-cn/102445)、[新版系统打开方式](https://developer.apple.com/news/?id=saqachfa)。


## 多选与分栏验证

`npm run test:e2e:editor` 现包含多选批量操作与分栏主流程，以及空列落点、跨页旧拖动、保存失败、锁定和长文滚动框选保护回归。测试数据和截图均为匿名样本，不读取私人导出包。共享验证流水线沿用该命令。安卓与苹果移动端仍只在远程流水线执行原生构建，本机仅验证共享界面。
