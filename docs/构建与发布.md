# 构建与发布

## 源码组织

五个平台共用一套源码。`ui/web/` 是共享界面，`crates/notebook/` 是共享核心，`src-tauri/` 是统一原生入口。移动端原生工程由 GitHub 流水线根据配置生成，不在项目中长期维护两份独立界面。

项目锁定前端与 Rust 依赖。构建使用锁文件，避免同一版本源码在不同时间获取不同依赖。

## 本机允许执行的操作

本机可编辑全部代码、运行共享核心测试、构建共享网页资源、验证手机尺寸布局，并编译当前桌面平台。移动端原生编译、链接和安装包构建仅在 GitHub Actions 执行。

```bash
npm ci
npm test
npm run check
npm run build
cargo test --locked -p notebook-core
cargo fmt --all -- --check
cargo clippy --locked -p notebook-core --all-targets -- -D warnings
npm run test:e2e
npm run desktop:dev
```

在当前系统打包桌面应用：

```bash
npm run desktop:build
```

界面测试使用独立临时工作区。苹果桌面本机使用已安装的浏览器，云端验证使用安装的测试浏览器。

## 流水线与版本

公开源码仓库为 [轻笺](https://github.com/a602017206/qingjian)，首版统一为 `0.0.1`。前端清单及锁文件、共享核心、原生应用和配置必须一致；`npm run release:check` 检查版本，发布流程额外要求标签为对应的 `v` 前缀版本。

| 文件 | 执行条件 | 产物或结果 |
| --- | --- | --- |
| `.github/workflows/verify.yml` | 主分支更新、合并请求、手动或发布流程调用 | 共享测试、静态检查、完整界面回归 |
| `.github/workflows/desktop.yml` | 手动或发布流程调用 | 两种苹果处理器、微软六十四位、Linux 桌面六十四位产物 |
| `.github/workflows/mobile.yml` | 手动或发布流程调用 | 安卓固定签名发布包、苹果模拟器应用及未签名真机包 |
| `.github/workflows/release.yml` | 推送版本标签或手动指定已有标签 | 所有验证及构建通过后，上传八种产物与摘要并发布版本 |

桌面原生任务使用对应系统执行器：苹果两种处理器分别构建，微软使用六十四位原生工具链，Linux 桌面在Ubuntu 22.04构建安装包和便携包。完整命令及目标架构见工作流矩阵；不在一个系统上伪装其他系统的安装包。

移动端入口会检查云端环境。本机只编写源码和运行平台无关测试，不执行移动原生编译。安卓先生成原生工程，使用指定平台工具、原生编译套件和JDK 17生成发布包，再进行对齐、固定密钥签名和验证。苹果两个移动任务分别对模拟器和真机平台无签名归档，打包时检查真实平台元信息，不能按文件修改时间猜测或将模拟器应用重命名为真机包。

## 免费签名与机密配置

安卓无需付费证书，使用本项目独立生成的固定密钥。仓库机密配置包含 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD` 和 `ANDROID_KEY_ALIAS`，只传给最终签名步骤。后续版本必须保留同一密钥，否则无法直接覆盖升级。

维护者本机备份在忽略目录 `.release-secrets/android/`，目录及口令文件限制访问权限。请另外妥善备份；不要随测试目录清理，不要提交源码或放进笔记仓库。云端机密配置不能用于找回明文私钥。更换或丢失密钥应明确通知使用者，不自动生成新密钥掩盖升级中断。

苹果桌面继续使用免费临时签名及完整性校验。微软桌面尚无付费代码签名证书。苹果手机没有共享证书或开发者账号，提供模拟器应用和需用户自行重新签名的真机包；免费账号通常需要七天续签，见[苹果手机免费安装说明](苹果手机免费安装说明.md)。不能直接安装未签名包，不能将模拟器包用于真机，也不声称已经完成真机验收。

## 发布与下载

统一版本后编写 `docs/发布说明/版本号.md`，创建并推送对应标签。标签不可覆盖，已公开版本不可用同名资产静默替换。工作流允许重新填充尚未正式发布的草稿；只有必要构建、测试和八种非空产物均通过，才会生成摘要、上传并将该版本设为最新版。

```bash
npm run release:check
git tag -a v0.0.1 -m "发布轻笺 0.0.1"
git push origin main
git push origin v0.0.1
```

下载资产使用固定平台名称，版本由标签目录区分。最新版地址位于 `releases/latest/download/文件名`，历史版本位于 `releases/download/标签/文件名`；说明页的下载表与徽章使用同一文件名。`SHA256SUMS.txt` 保存该版本全部平台文件的摘要。缺少产物、空文件或目录包含非发布文件时停止上传。

所有云端运行结果以版本页、工作流日志及验证报告为准；仅写好配置不能宣称已经构建成功。安卓与苹果移动端的构建也不等同于真机功能验收。

## 苹果桌面免费分发打包

在苹果桌面系统执行 `npm run desktop:build`，会构建应用，再自动进行临时签名、签名完整性校验和分发打包。构建端另需可用的Python 3，打包脚本只使用其标准库；接收方无需安装开发工具。

已有正式应用构建时，可以仅重新生成分发包：

```bash
npm run desktop:package:macos
```

默认生成：

- `artifacts/轻笺-苹果桌面.zip`：可直接转发，包含应用及「首次打开说明」。
- `artifacts/轻笺-苹果桌面.zip.sha256`：整个压缩包的校验摘要。
- `artifacts/首次打开说明.txt`：可单独发给接收方的中文说明。
- `artifacts/轻笺.app`：签名校验通过的应用副本。

打包先复制到临时目录，核对原字节、权限和符号链接，再对副本临时签名并执行严格完整性检查。压缩完成后重新核对全部条目、内容、中文路径编码和执行权限。任何检查失败都会停止出包，已有交付保持不变；通过后替换交付文件，旧文件保存在输出目录的 `.previous/` 下。分发文件和历史副本均不进入源码仓库。脚本不会修改用户安装的应用或笔记。

苹果云端桌面构建在原生编译后调用相同打包命令，发布时上传压缩包，并将摘要纳入统一校验清单，避免直接上传应用目录时执行权限丢失。微软和其他桌面的安装包类型继续沿用原配置。底层 `npm run tauri -- build` 只负责原生构建；转发给别人前应使用上述分发打包入口。

「首次打开说明」位于压缩包顶层，用户解压后可直接双击阅读。首次启动被系统拦截时，说明引导先尝试打开，再进入「系统设置 → 隐私与安全性 → 仍要打开」，按提示确认；不要求使用终端命令或关闭整体安全保护。遇到损坏、恶意内容或管理策略限制时，说明引导联系发送者检查，而非一律放行。

临时签名不等于开发者身份认证或苹果公证，也不能消除首次打开提示。本机验证只证明打包和完整性检查通过，不代表已在另一台电脑或受管理设备上验收。两种处理器的苹果桌面云端构建均已实际通过；下载自研处理器包后使用系统解压工具复核版本、架构、中文说明和签名通过。

依据：[苹果首次打开指引](https://support.apple.com/zh-cn/102445)、[新版系统打开方式](https://developer.apple.com/news/?id=saqachfa)。


## 多选与分栏验证

`npm run test:e2e:editor` 现包含多选批量操作与分栏主流程，以及空列落点、跨页旧拖动、保存失败、锁定和长文滚动框选保护回归。测试数据和截图均为匿名样本，不读取私人导出包。共享验证流水线沿用该命令。安卓与苹果移动端仍只在远程流水线执行原生构建，本机仅验证共享界面。


## 原生构建命令对照

以下命令在安装依赖后的对应系统执行器中运行，桌面追加锁文件约束；苹果桌面完成原生构建后仍需执行上文临时签名打包入口。

| 平台 | 原生构建命令 |
| --- | --- |
| 微软桌面六十四位 | `npm run tauri -- build --target x86_64-pc-windows-msvc --bundles nsis -- --locked` |
| 苹果桌面自研处理器 | `npm run tauri -- build --target aarch64-apple-darwin --bundles app -- --locked` |
| 苹果桌面英特尔处理器 | `npm run tauri -- build --target x86_64-apple-darwin --bundles app -- --locked` |
| Linux 桌面六十四位 | `npm run tauri -- build --target x86_64-unknown-linux-gnu --bundles deb,appimage -- --locked` |
| 安卓，仅云端 | `npm run tauri -- android init --ci --skip-targets-install` 后执行 `npm run mobile:android`，最后 `node scripts/sign-android.mjs` |
| 苹果手机模拟器，仅云端 | `npm run tauri -- ios init --ci --skip-targets-install` 后执行 `node scripts/configure-ios.mjs`、`npm run mobile:ios`，最后 `python3 scripts/package-ios.py --kind simulator` |
| 苹果手机真机未签名包，仅云端 | 同一初始化后执行 `node scripts/configure-ios.mjs`、`npm run mobile:ios-device`，最后 `python3 scripts/package-ios.py --kind device` |

安卓工具链的编译、归档和索引工具明确使用同一原生开发套件。苹果移动端静态嵌入压缩依赖，并通过 `scripts/configure-ios.mjs` 向生成工程加入系统字符转换库，再自动重建工程并验证链接项；不依赖框架会过滤的额外环境变量，无需维护两份独立界面或手工编辑工程。工作流是系统依赖、环境变量和签名配置的完整可执行依据。

## 安卓启动门禁与客户端版本检查

从零点零点二版起，正式发布额外依赖 `.github/workflows/android-startup.yml`。该流程仅在云端构建发布模式的模拟器测试包，分别验证安卓十六以及十六千字节页环境，进行三次冷启动、进程存活和工作台界面检查，保存日志与截图。测试包使用临时测试签名，不作为正式安装包发布；正式安卓包继续复用原有固定密钥。

`scripts/check-android.py` 检查安装包内所有原生库加载段的页对齐及边界，签名脚本另外检查压缩包对齐。原生链接通过 `src-tauri/build.rs` 设置最大与通用页大小，仅作用于安卓，不能只做压缩包对齐。

首次真实启动回归发现安全库在安卓上禁用文件证书接口，原应用在启动钩子读取根证书文件时失败并异常终止。安卓改为从内存解析内置根证书并加入信任库，保留证书和主机验证；信任库保留证书引用，本地对象按生命周期释放。相关直接依赖限定安卓，开发测试单独配置，不向微软版增加外部安全库探测依赖。

客户端通过公开正式版本接口查询新版本；系统、处理器和版本来自编译目标。只提供经过名称、来源和大小校验的对应下载地址，由系统浏览器下载。未发布标签、草稿或预览版本不提示更新；不支持的架构不降级到其他平台包。关于页面与后台检查共用状态，错误不冒充最新版，检查失败不阻塞本地笔记。

## 安卓认证的云端进程重启验证

从零点零点六开始，安卓启动验证流程的专用模拟器测试包启用 `credential-smoke` 编译特性，使用独立匿名条目验证系统安全凭据库：首次保存后强制结束进程；第二次启动读取同一账号和令牌并删除；第三次启动确认条目为空。普通页与十六千字节页的安卓十六模拟器均须通过，日志只输出阶段标记。

该特性仅供云端测试，正式移动端构建命令不启用。测试包为模拟器架构及临时测试签名，不作为手机升级包发布；手机使用正式流程生成、沿用固定签名的六十四位安装包。测试不连接真实私人仓库，不需要真实用户名或令牌，不能用测试成功代替具体手机和仓库权限的验收。


## 自动同步测试包

本轮自动同步按用户要求仅提供测试安装包，不创建版本标签，也不更新正式发布。测试包暂沿用零点零点六的统一版本；安装后通过工作区设置中的自动同步开关识别功能。覆盖安装保留数据与认证，建议先导出备份，不要卸载原应用。由于版本号相同，正式版本更新检查不会将此测试包提示为新版本。

`npm run test:e2e:auto-sync` 使用匿名本地裸仓库与两个工作区，验证启动、编辑防抖、同页冲突、网络失败后草稿、离线恢复、开关、手机属性编辑和恢复点操作。云端共享验证已加入此命令。苹果桌面在本机生成独立测试目录，安卓通过移动工作流指定完整源码提交并仅构建安卓，下载固定签名产物；不运行正式标签发布流程。
