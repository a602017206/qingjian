# 架构与数据格式

## 统一实现

项目分为三部分：`ui/web/` 保存五个平台共享的界面；`crates/notebook/` 保存共享 Rust 核心；`src-tauri/` 提供原生应用入口和系统插件权限。Git 使用内嵌库，手机无需安装命令行 Git，也不运行额外的服务进程。

界面通过单一业务调用入口请求保存、搜索数据、导入、版本历史与同步。原生应用直接调用 Rust；本地开发服务提供同一核心的本机接口，用于界面联调。开发服务只监听本机，正式应用不开放该服务。

系统数据目录由 Tauri 获取，保持各系统沙盒兼容。开发服务默认使用 `.data/`。可以通过环境变量 `QINGJIAN_DATA_DIR` 指定测试或开发数据目录。

## 数据目录

```text
config.json
workspaces/
  <workspace-id>/
    .git/
    workspace.json
    pages/
      <page-id>.json
    assets/
      <content-hash>.<extension>
```

外层配置保存工作区名称、远程地址、当前选择和界面偏好，不提交到笔记仓库。每个工作区独立拥有版本历史。应用安装包和编译缓存不进入笔记仓库。

## 页面结构

页面使用结构化文本保存，包含稳定标识、标题、图标、封面、父页面、标签、收藏、回收站状态、宽版、锁定、内容块、创建时间、更新时间和版本号。数据库页面另外保存属性定义与记录。

内容块包含稳定标识、类型、正文，以及对应类型的复选状态或代码语言。页面内引用使用 `page:<page-id>`，附件引用使用 `asset:<filename>`。用户也可以输入 `[[页面名称]]` 生成按标题匹配的页面链接。

稳定页面链接适合长期关联。按标题匹配的链接会受页面重命名影响。Markdown 导出保留这些专用链接；其他编辑器不会自动识别，完整迁移请使用结构化备份。

## 存储保护

- 保存使用临时文件、刷盘和替换，降低中断时写出半份文件的风险。
- 保存前检查磁盘中的版本号，拒绝旧版本覆盖新版本。
- 文件大小按实际序列化结果校验，单页上限为十六兆字节。
- 页面标识与文件名必须一致，内容块与数据库结构必须有效，页面层级不能循环。
- 回收站仅修改状态，保留内容及历史。恢复子页面时同时恢复必要的父页面。
- 当前编辑草稿额外保存在应用网页存储中，用于异常退出后的恢复；保存成功后清理对应草稿。
- 同步期间临时限制内容修改，避免远程刷新与当前输入发生竞争。

当前没有跨进程文件锁。不要让多个应用进程同时管理同一个数据根目录；同一应用中的操作由共享核心串行处理，页面版本号提供额外的覆盖保护。

## Git 同步

工作区创建为指定分支，默认 `main`。保存笔记不等于创建版本；点击「保存版本」创建提交。同步先提交笔记文件，再读取远程分支、获取版本、验证远程页面，并在可快进时更新本地工作区，最后普通推送。

双方都基于旧版本分别修改时，历史可能分叉。应用停止同步并保留本地提交，不强制推送、不自动重置、不把未完成的合并写入笔记。已暂存的非笔记文件也不会被应用悄悄提交。

所有平台统一支持 HTTPS，私有仓库认证由用户名和访问令牌组成。认证仅保存在当前进程内存中，退出后需要重新填写，不进入配置、页面或提交历史。首版不提供 SSH、持久化令牌和浏览器授权登录。

苹果系统使用系统证书校验。安卓和 Linux 使用项目包含的公开根证书集合；没有禁用 HTTPS 证书验证。证书集合来自 [公开证书集合](https://curl.se/docs/caextract.html)，应随应用依赖定期更新。自建服务使用未被信任的证书时，连接会失败。

## 导入与备份

Notion 导入解析压缩包中的 Markdown、HTML 和 CSV；按导出目录重建父子页面，并将本地页面链接和附件路径改写为稳定标识。附件按内容摘要命名，以减少重复导入相同文件造成的占用。

压缩包及解压总内容上限为一百二十八兆字节，文件数上限为一万，嵌套层数有限制。仅对不包含受支持笔记的外层压缩包装继续展开，已有笔记中的压缩附件保留原始字节，不自动解包。拒绝目录穿越、重复路径、符号链接和不合规页面。所有待导入文件先写入临时区域，成功后发布；失败时清理此次新增文件。

备份含版本标识、结构化页面、便于阅读的 Markdown、数据库表格和附件。恢复轻笺备份时按目录区分页面与附件，重新分配页面标识并更新内部引用，不重复导入辅助导出的 Markdown 和 CSV。首次恢复不会保留原 Git 历史；需要保留历史时应直接克隆笔记仓库。

HTML 导入剔除脚本、样式和活动嵌入，只提取基础可读内容。复杂布局可能变为文本；导入报告提示无法还原的内容。原始 Notion 导出包应保留作迁移核对。


## 高级数据库扩展

多选与关联的记录值使用标识数组的序列化文本，保持原有记录值为字符串的约定。公式、关联目标、汇总属性和方式保存于属性配置。记录正文保存在对应记录的正文属性。

所有平台使用相同的数据库计算模块，结果实时派生，不覆盖原始值。公式经过白名单语法解析，不执行动态脚本。完整备份恢复时重映射关联的目标数据库标识，记录标识不改变。

简易表格保存在内容块正文中，使用标准 Markdown 表格表示。导入 Markdown 表格时识别为可编辑表格块，导出仍保留表格文本。字面分隔符、转义符号和多行内容经过往返测试，重复选择表格类型不清空已有内容。


## 网页导出来源与字段还原

导入识别网页页面结构、数据库表格和子页属性。显式网页类型及选项颜色优先于纯表格内容推断；配套完整表格保留全部字段，来源别名映射到同一父页面。来源文件、网页页面标识、字段原始值及属性快照用于核对，数据库行另保存原始记录标识、链接与关联子页标识。

数值核对采用无损十进制文本规范化，不经过浮点转换；相同可见值对应多个候选时不归并。链接、页面标识和原始值矛盾时保留数据并报告。已有平铺数据不自动迁移。

数据库单元格链接和图片按记录及字段保留为正文内容块，导入时转换内部页面与附件引用，随后沿用备份和附件保护机制。属性装饰图标不转成正文，网页脚本不执行，远程媒体地址不自动下载。


## 数据库子页面属性布局与来源定义

数据库保存子页面的属性显示顺序及可见性，使用稳定字段标识而非名称关联。显示规则分为始终显示、仅非空显示、隐藏；布局不修改表格记录的值。普通字段按原值判断空，集合按元素判断，计算字段按结果判断。

从导入子页修改字段结构前，额外保留原字段定义快照，供原有属性正文的核对使用。重命名和删除不会把未改动的旧属性文字误当成新正文；原始内容和来源值仍保留。新增元数据随结构化备份和版本存储保存，不依赖导出样本或应用缓存。

## 属性扩展与记录元信息

人员值保存为名称数组的序列化文本，媒体值保存为文件对象数组，包含原名称、可选附件引用或网页地址。位置值保存为地址及可选经纬度对象的序列化文本。未知字段和来源值继续保留。字段配置增加按钮目标和值、按钮名称及编号前缀，均随页面备份和版本保存。

数据库行保存创建与编辑时间、作者和稳定序号，数据库持久化下一个序号。共享核心维护元信息，保护已有创建信息和序号；值或行正文变化更新编辑信息，空字段及布局变化不更新。保存返回的元信息在界面单独合并，不覆盖保存期间的新编辑。子页面正文保存保持单页面事务，编辑属性计算使用行及关联子页的较新编辑信息。

媒体字段参与现有附件引用扫描、备份及回收保护；本地文件引用格式与按钮目标在核心再次校验。网页导出能识别显式人员、媒体、邮件、电话和系统属性；来源链接无法找到时保留并告警。导入未知作者保持空值，界面显示未知。

## 侧边记录与相邻弹层

侧边预览仅保存界面状态，真实子页仍使用原页面保存路径，属性仍保存到父数据库。普通行没有独立子页时直接编辑数据库行标题和正文。界面目标校验包含工作区、父数据库、当前页面及预览记录，过期弹层不能写到另一记录。关闭及切换先等待串行保存，失败保留目标和草稿。

父页面背景保留原始布局及滚动位置，字段数据从当前草稿重新生成；背景字段和正文保持只读，记录打开和视图入口继续可用。背景资产只保留稳定引用，旧临时链接和加载标记在重绘时清除，附件重新读取；已加载图片保留占位高度以避免位置变化。背景副本仅在内存中存在，不进入笔记、备份或版本仓库。

属性弹层按触发位置和窗口边界定位，手机使用底部面板。窗口尺寸变化只重新定位，不销毁尚未提交的表单。选项值复用自动保存队列，字段配置保留显式保存。共享核心及原数据格式在本轮保持兼容。
