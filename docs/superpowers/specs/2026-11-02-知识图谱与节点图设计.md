# 知识图谱与节点图设计方案

日期：2026-11-02
状态：设计草案，供评审；尚未实现
范围：轻笺本地优先笔记工作区，覆盖桌面和移动端。

## 1. 目标与边界

在已有页面、数据库、标签和页面链接之上，增加两种互补能力：

- **知识图谱**：根据工作区已有数据自动展示页面之间的关系，帮助发现关联、回溯来源和浏览上下文。图谱是可重建的视图，不是另一套笔记数据库。
- **节点图**：用户主动创建和编辑的图，首期包含类似 XMind 的思维导图和通用节点连线。节点可引用现有页面，也可只是图中的文字，不要求每个节点都是笔记。

它们共享画布、导航和链接能力，但数据来源、编辑语义和保存方式不同。首期不做多人实时协作、在线图谱服务、自动语义抽取、任意流程图形状、跨工作区链接或承诺完整 XMind 格式互通。后续可扩展，但不能为了未来需求先引入图数据库或云服务。

## 2. 当前项目基础

- `ui/web/` 为桌面和移动端共用界面，`crates/notebook/` 为共享 Rust 核心，Tauri 提供系统能力。
- 每个工作区独立拥有 `workspace.json`、`pages/<page-id>.json`、`assets/` 和 Git 历史。页面有稳定 ID、父页面、标签、块、版本及回收站状态；单页面序列化上限 16 MiB。
- 页面正文支持 `page:<page-id>` 和 `[[页面名称]]`。前者适合稳定引用；后者依赖标题。当前页面详情中的反向链接是基于块文本的简单匹配，不能直接当作完整、无歧义的关系索引。
- 数据库关联存在于属性与记录中；部分记录有独立子页面，部分记录正文保存在数据库页面。当前页面备份恢复会重新分配页面 ID 并改写内部引用。实际字段和迁移逻辑以实现时的代码及测试为准。
- 保存有原子替换、版本检查、草稿保护；Git 同步在历史分叉时停止，保留双方数据。不能假设当前支持跨文件事务或跨进程文件锁。

## 3. 典型使用场景

| 场景 | 用户动作 | 预期结果 |
| --- | --- | --- |
| 研究某个概念 | 打开文章，点击“查看关联图谱” | 以当前页面为中心，看入链、出链及来源，点击跳转 |
| 梳理知识库 | 从侧栏打开“知识图谱”，筛选标签、关系和范围 | 发现孤立页面、连接较多的主题以及页面层级 |
| 规划课程或项目 | 新建思维导图，创建主题和子主题 | 形成可折叠的树，节点可关联项目页面 |
| 设计流程或依赖 | 新建自由节点图，连线并标注关系 | 表达非树状、多对多的关系；方向与标签可见 |
| 在笔记中引用图 | 文档中插入已有节点图引用 | 文档中直接显示只读图预览，可点击进入完整图页面；引用与原图身份稳定 |
| 手机复习 | 打开图谱或节点图，点击节点 | 聚焦周边关系、跳转页面；使用列表替代复杂拖拽 |
| 迁移或离线工作 | 备份、恢复、同步后打开图 | 图的内容仍可编辑，页面关联正确重映射；图谱可重建 |

## 4. 方案对比与推荐

| 方案 | 做法 | 优点 | 代价与结论 |
| --- | --- | --- | --- |
| A. 图谱和画图都写入独立图数据库 | 维护单独节点、边和笔记副本 | 查询灵活 | 复制事实、同步与备份复杂，不符合当前架构；不推荐 |
| B. 图谱派生，节点图作为普通页面的结构化内容 | 图谱从页面数据计算；用户绘图写入页面 JSON | 沿用工作区隔离、版本、备份和回收站；概念清楚 | 单图仍是页面级冲突；推荐 |
| C. 节点图保存在专用文件目录 | 每张图独立文件，页面保存引用 | 大图可独立于页面 | 需要扩展 Git 文件白名单、原子发布、备份、回收站和远端验证；首期不选 |

推荐 B：节点图是一种带 `diagram` 数据的普通页面，文档中通过既有页面引用指向它，并可显示从原始图数据生成的只读预览；完整编辑在图页面进行。知识图谱只读取关系，不凭一次拖线修改源笔记。后续可在证明安全性和需求后评估文档内直接编辑。

## 5. 信息架构与入口

1. **左侧导航**：在工作区级导航中加入“知识图谱”，位于搜索等工作区工具附近；切换工作区后重新加载，不能混入其他工作区。
2. **普通页面**：页面更多操作和详情中的“查看关联图谱”，以本页为中心；入链、出链列表可先行交付。节点详情可直接打开页面或侧边预览。
3. **新建入口**：新建页面时可选择“思维导图”或“自由节点图”；两者都是普通页面，保留目录层级、收藏、搜索、回收站和页面操作。
4. **正文预览**：通过斜线菜单“思维导图预览”选择已有图页面，使用稳定 ID 引用；文档内直接展示可缩放查看的只读图预览和“打开编辑”入口。也可切换为紧凑页面链接；重命名后引用继续跟随 ID。
5. **图页面**：标题与普通页面一致，正文主体为画布，工具栏提供撤销、重做、适配视图、保存状态与导出；锁定或预览时不可编辑。普通页面的标题、标签、历史、同步规则继续有效。
6. **手机**：图谱默认聚焦当前节点并提供可搜索关系列表；图页支持缩放、平移、选择及基本节点编辑。复杂多选/大规模拖动以桌面优先；不能操作的功能明确禁用并说明，而不是静默丢失。

## 6. 知识图谱的规则与交互

### 6.1 节点与关系

首期图谱节点为**当前工作区未删除、非模板的页面**，包括图页面与拥有独立子页面的数据库记录。普通数据库行没有独立页面 ID，首期不作为独立图节点；其正文、属性链接暂不声称覆盖，后续通过复合身份及性能验证再引入。模板和回收站默认不参加图谱；失效目标通过诊断列表呈现，不生成可误认成真实页面的节点。

| 关系类型 | 来源 | 方向 | 默认 |
| --- | --- | --- | --- |
| 页面引用 | 支持的正文链接 `page:<id>` | 来源页 → 目标页 | 开启 |
| 标题引用 | `[[名称]]` 经唯一匹配 | 来源页 → 目标页 | 开启，并标记为标题匹配 |
| 页面层级 | `parentId` | 父页 → 子页 | 可筛选，默认关闭 |
| 同标签 | 两页含同名标签 | 无向、派生 | 首期仅列表筛选，不生成两两连线，避免组合爆炸 |
| 数据库关联 | 数据库记录关联属性 | 记录 → 记录 | 后续阶段，先明确目标记录及无子页身份 |
| 节点图页面引用 | 图节点里的 `pageId` | 图页面 → 被引用页面 | 节点图阶段加入，标记来源为图节点；图内普通连线不会自动成为笔记之间的关系 |

同一来源与目标可有多个来源位置；展示时可合并为一条带数量的边，详情列出块 ID、来源类型及上下文。自链接显示在详情而默认不画环。解析应复用或抽取与渲染一致的链接语义；代码块、转义文本和普通外链不得误识别为页面引用。标题唯一匹配且目标未删除才形成边；重名、空匹配及失效 ID 显示在“待处理链接”中，保留原文，不自动改写。标题改名可使标题引用失效，应提示用户可手动转换为稳定 ID。

### 6.2 交互与状态

- 全局视图：搜索、按标题/标签/关系类型筛选，展示孤立页面；节点点击查看名称、入链/出链、关系来源，双击或按钮打开页面。默认限制展示数量，提示当前显示/总数及继续筛选。
- 局部视图：当前页面为中心，默认一跳，可选择二跳；方向、来源和目标清楚可辨。移动端优先列表，保留画布切换。
- 图谱缩放、平移和会话筛选只保存在本机或内存，不写进笔记仓库；自动布局结果是可丢弃缓存。首期拖动节点只调整当前会话显示，不表示编辑笔记或关系。
- 关系索引按工作区派生，可放内存，必要时使用工作区隔离的本机缓存；不提交 Git、不进入备份。页面保存、删除/恢复、导入、同步和工作区切换后失效更新；异常可全量重建。更新期间显示索引中状态，不显示虚假的完整结果。

## 7. 节点图模型与交互

### 7.1 两种模式

- **思维导图**：一张图一个根节点，其他节点恰有一个父节点，整体无环且连通。Tab 新增子主题、Enter 新增同级、折叠分支、拖动改变顺序与父级；自动布局为主。重新挂载不能形成循环；删除分支前显示影响范围并可撤销。
- **自由节点图**：支持独立节点、多个入/出边、有向或无向边、边标签、节点位置。可画循环；删除节点时提示关联边并作为一次可撤销操作一并移除。首期只提供基础矩形/圆角节点和连线，不承诺 BPMN 等语义。
- 复制节点时生成新节点 ID；复制选区内边时生成新边 ID 并重映射端点。引用页面 ID 不随图内复制改变。首期不支持模式相互转换，以免丢失树或布局语义。

### 7.2 文档内直接预览

预览复用普通页面引用块（稳定 `page:<id>`），通过块上可选的 `diagramPreview: true` 声明展示方式；不复制节点数据，也不保存生成的图片。斜线菜单选择已有思维导图后插入引用；已有图页面链接可在条目菜单切换预览/链接。复制引用块保留相同目标，删除或撤销该块只影响引用，不删除原图；目标必须先存在并保存成功，首期不提供在插入时跨页面同时创建图的事务。

预览从当前工作区目标页的已保存 `diagram` 数据渲染，标题、加载状态和“打开编辑”入口始终可见；普通点击/滚动不劫持文档滚动，提供明确的放大查看按钮，手机通过全屏只读视图查看。锁定、只读预览和数据库侧览中均不可从预览编辑原图。目标发生保存、恢复、删除或同步更新后，按工作区和页面 ID 失效并重新渲染；图页面有未保存草稿时，预览显示已保存版本并提示，不能冒充草稿已保存。目标缺失、位于回收站、格式不支持、损坏或加载失败时保留引用并显示对应状态与重试/打开入口；绝不自动删除引用。

初始高度有上限，过大的图默认适配并可放大；采用视口懒加载、相同目标共享内存结果和资源释放，预览不持久化到笔记仓库。渲染异步返回时核对工作区、引用块、目标 ID 与修订号，避免切页或同步后展示过期图。完整结构化备份应通过既有块链接重映射机制处理预览引用，并以专门测试证明；Markdown 导出至少保留可读图标题和稳定链接，不能宣称导出文档保留可交互预览。旧版本对新增块字段的保留仍须实际验证。

### 7.3 编辑与链接

节点可编辑文本、颜色和可选页面引用。引用以稳定页面 ID 保存；节点文本是用户可独立编辑的标签，不随页面改名自动覆盖；详情显示目标当前标题。打开目标、解除引用和替换目标有明确入口。失效/回收站目标显示原标签与失效状态，恢复目标后关系重新有效；删除节点不删除笔记，删除引用也不删除图节点。

先提供链接到已有页面；“从节点创建页面”涉及两个页面的独立写入，后续单列设计。首期节点图不自动将线条写成正文链接，也不隐式创建任何页面关系。文本输入支持中文输入法组合、键盘焦点、复制粘贴、撤销重做；拖动结束才形成一次修改及保存，切页、切工作区、锁定、同步期间遵循现有草稿与操作保护。

## 8. 持久化格式与数据生命周期

### 8.1 唯一事实来源

节点图使用普通页面 `pages/<page-id>.json` 中可选的 `diagram` 对象；已有 `blocks` 保持兼容，可为空。以下字段为建议格式，具体类型和上限需在实施测试中锁定：

```json
{
  "id": "page-diagram-id",
  "title": "项目规划",
  "blocks": [],
  "diagram": {
    "schemaVersion": 1,
    "mode": "mindmap",
    "nodes": [
      {"id": "node-1", "text": "项目", "pageId": "", "parentId": "", "order": 0, "collapsed": false},
      {"id": "node-2", "text": "调研", "pageId": "existing-page-id", "parentId": "node-1", "order": 0, "collapsed": false}
    ],
    "edges": [],
    "style": {"theme": "default"}
  }
}
```

自由图采用 `schemaVersion: 2`（思维导图仍为版本 1），使具有版本保护的旧核心拒绝覆盖；自由图的节点使用有限数值坐标 `x`、`y`；边保存 `id`、`sourceId`、`targetId`、`directed` 和 `label`。思维导图的树结构以节点 `parentId` 和同级 `order` 为唯一事实来源，不再重复保存父子边；跨分支附加关系首期不支持。是否折叠是图内容的一部分并随版本同步；当前缩放、平移、选中状态是本机视图状态，不同步。可选样式为有限枚举，不保存可执行内容。所有 ID 在各自作用域唯一；画布文字可为空，页面引用为空或为同工作区稳定 ID。

建议首期单图最多 2,000 节点、4,000 条边，节点文本最多 8 KiB，边标签最多 2 KiB；仍须受现有 16 MiB 页面整体上限约束。达到限制时提示并拒绝新增，不截断。性能目标应由实测调整，不能把这些数字当作已验证性能。

### 8.2 核心校验、保存与故障

共享核心在本地保存、完整备份恢复、远程读取时验证版本、节点/边唯一性、端点存在、坐标有限、引用格式、树根和无环约束、字段长度及规模；未知更高 `schemaVersion` 采用保留原始数据并拒绝编辑的保护策略，不能自动删除或降级。失效页面引用允许保存并显示问题，避免目标删除导致图无法恢复。校验失败拒绝整页写入，并保留原文件、草稿和明确错误；加载损坏页面不能静默跳过或覆盖。

图编辑与页面标题共用现有页面修订号、原子写入、串行队列、草稿恢复和锁定状态。画布草稿应包含完整 `diagram` 和版本，按工作区及页面隔离；保存回包只合并对应确认版本，不能覆盖提交期间新编辑。超限、磁盘失败、版本冲突均显示未保存并保留草稿。回收或删除页面前先处理未保存编辑；撤销、恢复和回收站沿用页面生命周期。

### 8.3 多设备与旧客户端

节点图与其他页面一样提交到当前工作区 Git；同一图在两端离线修改时以页面为冲突单位，禁止宣称节点级自动合并。历史分叉沿用现有停止、保留双方提交及恢复点、人工核对流程；版本对比应至少显示节点数、边数及双方图预览/文本摘要，不能在无法解析时覆盖任何一方。不同图页面的更改也仍由现有 Git 同步策略决定，不能保证自动合并。

旧版本不认识 `diagram`：保留未知字段是否能在读取、编辑、备份和冲突恢复中贯通尚未验证，旧版本也可能将图当作空白页面。发布前必须用真实旧版本开展往返和破坏性回归；若无法可靠阻止旧版本写入，要求用户先升级所有设备、提示备份，并在发布说明标出旧版不可安全编辑图页面。新版本对于未知更高版本只读的保护不能约束已经发布的旧客户端，不能声称它能彻底防止旧版覆盖。

### 8.4 备份、导入与导出

- 结构化完整备份包含 `diagram` 全部数据。恢复时先构造完整页面 ID 映射，再递归重映射图节点 `pageId`；同一工作区内找不到的目标将原 ID 保存到 `unresolvedPageId` 并报告，清空活动引用，避免碰巧关联到其他页面；用户重新选择后移除待核对标识。图内节点和边的局部 ID 保持或整体一致重映射；重复导入不同图页面不发生身份冲突。
- 图页面复制或作为模板应用时新建页面 ID；复制整图可保留只在图内使用的节点/边 ID，但所有内部端点必须一致；页面引用仍指向原目标。节点图模板首期不开放，直至克隆语义和导入测试完成。
- 可读导出首期提供 Markdown：思维导图导出分级大纲，自由图导出节点清单和带方向的关系列表，页面引用附稳定链接；明确告知它不是无损往返格式。图形导出 PNG/SVG 作为后续阶段，须处理字体、画布边界和 SVG 安全；不把图像当作唯一备份。
- XMind 导入/导出属于后续独立兼容工作，先验证格式版本、许可证、可表达范围，提供不支持内容清单和导入报告；不得宣称完全兼容或静默丢弃。Notion 导入保持原行为。

## 9. 架构分工与实现落点

| 位置 | 建议职责 |
| --- | --- |
| `crates/notebook/src/` 新增图模型/校验模块，接入 `lib.rs`、`import.rs` 等 | schema 校验、页面引用重映射、备份、远端校验与错误报告；沿用现有页面持久化 |

## 10. 性能、可访问性与体验指标

- 目标测试集：100、1,000、5,000 页面，分别模拟稀疏与高连接；节点图测试 100、500、2,000 节点。记录桌面与中档手机的索引耗时、首次可交互时间、缩放/拖动流畅度和内存峰值。发布门槛先经目标设备实测再定；超预算时默认局部图、限制显示或转列表，不影响保存。
- 大图按视口裁剪、限制标签数量，布局可取消；过期异步结果必须检查工作区和数据代次，不能覆盖新图。长任务展示进度/取消，索引故障可重试。
- 提供键盘可达的节点列表和关系列表、焦点/选中状态、屏幕阅读器名称与可见标签；不依靠颜色或线条方向单独传达信息。保留常用快捷键，输入法组合期间不触发结构操作。
- 节点或边存在数千项时搜索和筛选仍应可用；触屏区足够大，双指缩放与页面滚动行为清晰。首期移动端能力与限制应在界面和文档说明。

## 11. 分期与验收

### 阶段 0：风险验证

验证链接语法真实覆盖、图页面字段在现有保存/同步/备份流程中的表现及旧客户端风险；建立性能样本和画布技术原型。给出可复现结果后确定依赖和兼容策略。此阶段不修改真实用户数据。

### 阶段 1：思维导图数据安全与编辑

先完成可复现的失败测试和兼容验证，再实现图页面结构、树编辑、页面引用、撤销、自动保存、回收恢复、备份重映射与 Markdown 大纲导出。验收：离线重启后完整恢复；拖动不能生成环；备份恢复后引用正确；失败时保留草稿；旧版风险按验证结果明确控制。

### 阶段 2：文档内预览与首版发布

交付插入已有思维导图、只读预览、移动端查看和进入编辑；覆盖引用的复制、删除、更新、回收站、缺失目标和同步切换。验收：文档可直接看到图；同一原图多处引用不复制数据，修改后刷新；预览不生成仓库图片；结构化备份恢复后目标不串链。阶段 1 和 2 一起构成首版交付。

### 阶段 3：关系基础与局部、全局知识图谱

先写失败测试，实现统一链接提取、关系来源与失效链接提示，再交付局部和全局图谱、筛选、搜索及可重建索引。验收：重复标题不误连，代码块/转义不误解析；工作区切换无串数据，手机能通过列表导航。

### 阶段 4：自由节点图与互操作

交付节点位置、多对多连线、方向、标签和 Markdown 关系导出；图节点对页面的引用纳入知识图谱。之后再评估图片导出、XMind 兼容、数据库记录关系和高级布局。

每阶段分别覆盖 Rust 数据校验及备份测试、前端关系/结构单测、桌面和手机端到端测试；尤其覆盖同步分叉、磁盘失败、过期回包、导入失败和异常退出。现有功能回归通过后再进入下一阶段。

## 12. 待评审的产品决策

1. 用户已确定先做思维导图，首版包含文档内直接预览；阶段 1、2 必须一起验收。
2. 首期数据库普通行不成为图谱节点；若日常使用以数据库记录为主，需要提前为记录设计跨数据库稳定身份与关系提取。
3. 文档内首版直接展示只读预览，完整编辑在独立图页面；预览不另存图片。
4. 实施前需确认图页面在现有页面校验、完整备份及旧版中的实际表现，测试未完成前本方案的格式只是建议，不代表现有功能。

## 13. Git 仓库体积与控制

思维导图的结构化 JSON 和笔记一起进入 Git 历史；每次保存版本或有变更时同步，可能增加 `.git` 和远端仓库大小。应用的本地自动保存本身是写工作文件，并不等于每次产生 Git 提交；同步开始时会执行保存版本，无内容变化则复用现有提交。Git 保存内容快照，重复对象可复用，打包后相近版本通常可使用增量压缩；具体增长取决于编辑次数、图规模、压缩打包及附件，不能假设每次都增加完整文件大小，也不能保证只增加差异大小。

首期控制措施：图只存结构化文本，不把预览快照、布局缓存或每次导出的图片自动加入仓库；自动布局默认不持久化每个节点坐标；节点稳定 ID 和稳定序列化减少无意义变化；仅变更时写入，避免查看/预览触发保存。沿用原有同步配置和显式保存，不为了压缩历史擅自延迟或丢弃用户指定的版本。用户主动插入、修改的图片附件可能成为主要空间来源，删除工作区文件或清空回收站并不自动移除历史中的对象。

验证时以同一生成数据集测量图的 JSON、工作区及 `.git` 大小：建立空库基线，分别编辑小图/大图 10、100 次并保存版本，比较预览开关、重复打开及有无附件的增长；同时分别测量正常保存后的状态和受控副本中 Git 打包后的状态。打包可压缩对象但保留可达历史；测量不能承诺精确压缩比例。不可达对象何时被清理取决于引用、保留期及仓库维护状态；自动清理、历史截断、强制推送和后台重写历史均不纳入首版。若未来需要清理旧历史，必须单独设计并明确提醒会影响历史恢复和多设备同步，先备份并由用户决定。
