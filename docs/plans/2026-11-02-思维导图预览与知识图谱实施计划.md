# 思维导图、文档内预览与知识图谱实施计划

> 执行时参照 `executing-plans` 技能逐项实施；本文件是计划，不代表功能已经存在。

**目标：** 先交付可离线编辑、可靠同步与备份的思维导图，并在普通文档内直接预览；随后交付知识图谱及自由节点图。

**架构：** 思维导图作为普通页面的可选 `diagram` 数据，文档预览使用指向该页面的稳定引用并从已保存数据只读渲染。图谱从页面关系派生，缓存不作为真实数据；保留现有工作区隔离、页面修订校验、备份和 Git 策略。

**技术栈：** 现有 Rust / `serde_json` / `git2`，原生 JavaScript ES modules、Tauri WebView、Node 测试与 Playwright。具体画布实现或外部依赖以阶段 0 验证结果为准。

**设计依据：** [知识图谱与节点图设计方案](../superpowers/specs/2026-11-02-知识图谱与节点图设计.md)。本计划不授权自动提交、推送、重写 Git 历史或清理用户数据；现有工作区可能包含其他未提交修改，实施前先检查并保留。

---

## 执行约束

- 用户可见文案进入 `ui/web/i18n.mjs` 的简体和繁体字典。各阶段的设计与实现均追加到当天 `docs/每日记录/` 已存在的唯一记录；没有记录时按约定新建。
- 修改存储、导入、同步前先新增失败测试并运行，确认失败原因是缺失功能；然后最小实现并重跑。先验证具体测试目标存在，以下新文件和命令是实施任务的预期目标，而非现有文件。
- 不引入仓库内图片预览缓存；不绕过现有页面修订、草稿、锁定、同步冲突和附件保护；所有失败必须保留数据与可恢复草稿。
- 首版 = 阶段 1 和阶段 2 一起完成。阶段 0 是发布门槛；阶段 3、4 可独立排期。任务路径为计划落点，执行时根据实际模块边界微调并记录理由。

## 阶段 0：基线与技术风险

### 任务 0.1：锁定基线及兼容试验

**读取：** `crates/notebook/src/lib.rs`、`crates/notebook/src/blocks.rs`、`crates/notebook/src/import.rs`、`crates/notebook/src/git.rs`、`crates/notebook/src/sync.rs`、`ui/web/app.mjs`、`ui/web/page-links.mjs`、`ui/web/editor.mjs`。

1. 记录现有页面保存、版本冲突、完整备份重映射、远端检查及页面链接块实际行为；使用临时工作区运行基线测试，不触碰真实笔记。
2. 构造带未知 `diagram` 字段和预览字段的独立样本，分别用当前版本及能够取得的已发布旧版本进行打开、普通编辑保存、结构化备份/恢复和同步测试，比较完整 JSON。旧版不可获得时记录未验证，不能做兼容承诺。
3. 若旧版可能覆盖内容，保留用户全设备升级、备份及发布提示作为硬性发布条件；新版本必须对未来未知图版本拒绝编辑，不能把这误说成旧版防护。
4. 运行 `npm test`、`cargo test -p notebook-core` 并记录已有失败，后续仅以相同基线比较；环境不可运行时记录原因。

**完成标准：** 有各路径证据、明确风险和可执行发布条件；不能证明无损的旧版路径视为不安全。

### 任务 0.2：画布与仓库体积试验

**建议新增实验脚本：** `scripts/bench-mindmap.mjs`；样本和 Git 仓库只放临时目录或被忽略的测试目录。

1. 准备 100、500、2,000 节点树，测量桌面/手机 WebView 的首次渲染、展开折叠、缩放及内存；比较可访问性、文字输入、触控和离线能力，确定 SVG/Canvas 或合适依赖及许可证。
2. 基于固定样本创建 Git 仓库，测量首次提交、10/100 次真实节点修改提交、只打开预览、插入/替换附件后的工作文件和 `.git` 大小；在**仓库副本**打包前后分别统计。标注数据与 Git 版本、平台、节点数和提交数；不把打包结果泛化为保证。
3. 验证仅查看与预览不会改文件或产生新提交；形成观察结果和性能预算。超过预算时先削减可见节点、支持懒加载或以列表降级，不牺牲数据。

**完成标准：** 选定技术路径，给出可复现数据，列出未达标项及处置；无论结果如何不对用户仓库运行清理或历史重写。

## 阶段 1：思维导图数据和编辑

### 任务 1.1：模型与共享核心校验

**新增：** `crates/notebook/src/diagram.rs`、`crates/notebook/tests/diagram_validation.rs`。
**修改：** `crates/notebook/src/lib.rs`；必要时扩展 `crates/notebook/src/blocks.rs`。

1. 先写失败测试：合法单根树可保存并重新读取；空图/多根、重复 ID、孤儿、环、重复同级顺序、超上限和非法字段拒绝；失效页面引用不破坏图；未知更高 schema 不被静默清除。测试保存失败后磁盘原文件不变。
2. 运行 `cargo test -p notebook-core --test diagram_validation`，确认因模型/校验缺失失败。
3. 按设计的 `schemaVersion`、`mode`、`nodes`、`edges` 实现最小校验，在 `validate_page` 接入；树的唯一事实为 `parentId` 和 `order`，保留兼容旧页面和未知字段。对未来版本定义可读取保留但不可编辑的处理入口，不能使它被默认保存路径覆盖。
4. 重跑该测试及 `cargo test -p notebook-core`。核对页面整体 16 MiB 限制以及 UTF-8 字节长度，错误返回不包含私有正文。

**验收：** 老页面无需迁移即可打开；非法图不写盘；新版本无法把未来格式当空图保存。

### 任务 1.2：备份、复制、历史与同步安全

**新增：** `crates/notebook/tests/diagram_backup.rs`、`crates/notebook/tests/diagram_sync.rs`。
**修改：** `crates/notebook/src/import.rs`、相关页面复制及同步验证模块。

1. 先写失败测试：完整备份恢复时图节点 `pageId` 随映射正确转换；引用缺失保留并报告；含预览引用的普通块恢复后正确定位新图；图内 ID/父子结构不丢失；同名页面不串链。
2. 测试图页面复制、回收恢复、手动历史还原、版本冲突和两个设备独立修改后分叉；断言无无提示覆盖，失败时双方或恢复点可找回。按现有同步测试夹具创建真实 Git 测试库。
3. 分别运行 `cargo test -p notebook-core --test diagram_backup` 和 `cargo test -p notebook-core --test diagram_sync` 并确认失败；实现重映射及校验，重跑直至通过。
4. 检查 Git 收集范围仍为页面、附件和工作区元数据；图不生成新的仓库目录，也不提交预览图片或缓存。

**验收：** 跨工作区恢复、冲突与目标缺失均可解释且不丢数据；旧版风险按任务 0.1 结果发布。

### 任务 1.3：树编辑纯逻辑与保存队列

**新增：** `ui/web/mindmap-model.mjs`、`tests/mindmap-model.test.mjs`。
**修改：** `ui/web/app.mjs` 及现有草稿/保存相关模块，必要时提取独立控制器。

1. 编写失败测试覆盖新增根/同级/子级、排序、拖动更换父级、禁止自挂或后代挂载、折叠、整分支删除与撤销、复制子树生成新节点 ID 和保留外部页面引用。
2. 运行 `node --test tests/mindmap-model.test.mjs` 确认失败，编写不依赖 DOM 的纯函数与可撤销命令，重跑通过。
3. 以工作区、页面 ID、页面对象及编辑序号绑定异步保存；拖动结束形成一个编辑动作，失败保留含完整图的草稿；旧回包不能覆盖新编辑。复用现有锁定、预览、同步冻结和 `flush` 机制，避免单独建立不兼容保存路径。
4. 添加模拟保存失败、连续编辑后乱序返回、切工作区与异常恢复测试，连同 `npm test` 运行。

**验收：** 关键操作可撤销；未保存状态明确；关闭/切换不丢草稿，不写入错误工作区。

### 任务 1.4：思维导图页面与跨端交互

**新增：** `ui/web/mindmap-view.mjs`、`ui/web/mindmap-editor.mjs`、`tests/e2e/mindmap-editor.mjs`。
**修改：** `ui/web/app.mjs`、`ui/web/style.css`、`ui/web/i18n.mjs` 及实际新建页面入口。

1. 实现新建思维导图页面、渲染树、编辑节点文本、Tab/Enter、重排、折叠、关联已有页面、打开目标、缩放与适配；图页面仍享有标题、目录、收藏、锁定、回收站及搜索。
2. 提供键盘可达的节点列表和可访问名称；中文输入法组合期间不执行结构快捷键。手机支持选择、添加、改名、折叠、查看与平移缩放；不支持的操作明确呈现。
3. 先建立端到端用例，再运行 `cargo build --locked -p notebook-core --bin server` 和 `node tests/e2e/mindmap-editor.mjs`。覆盖桌面/窄屏、键盘、输入法、重启、回收恢复和锁定，补充对应前端单测。
4. 运行 `npm run check`、`npm test` 以及与编辑器、移动端、同步相关的既有测试；对比阶段 0 基线并记录结果。

**验收：** 能新建并完整编辑一张图，重启后保持结构；失败不会伪装成已保存。

## 阶段 2：文档内直接预览及首版发布

### 任务 2.1：预览引用和正文交互

**新增：** `ui/web/diagram-preview.mjs`、`tests/diagram-preview.test.mjs`、`tests/e2e/diagram-preview.mjs`。
**修改：** `ui/web/block-menu.mjs`、`ui/web/editor.mjs`、`ui/web/app.mjs`、`ui/web/i18n.mjs`、`ui/web/style.css`；必要时调整核心块校验和备份测试。

1. 先写失败测试：斜线菜单选择已有图后插入带 `diagramPreview: true` 的稳定页面引用；文档可见图形；切换链接/预览、复制和删除只改变引用块，不改变图；锁定页面不可编辑引用。
2. 先运行 `node --test tests/diagram-preview.test.mjs` 确认失败，再复用页面引用语义实现块表现；严格避免为预览再存一份节点数据或图片。
3. 使用图页面**已保存**修订生成只读预览。提供加载、打开编辑、显示未保存草稿提示、缺失/回收/损坏/不支持版本的状态和重试；预览滚动与页面滚动不冲突，手机提供全屏查看。
4. 目标更新时按工作区、目标 ID 和修订号失效；懒加载并核对异步代次，取消或丢弃过期回包。测试一图多处引用、切换工作区、目标删除恢复、同步替换和草稿未保存。
5. 运行 `node --test tests/diagram-preview.test.mjs`、`node tests/e2e/diagram-preview.mjs`，以及任务 1.2 的备份恢复测试；核对恢复后预览引用指向映射后的图。

**验收：** 文档中无需跳转即可看到图；所有预览从唯一图数据派生；目标变化正确刷新，错误不删除原引用。

### 任务 2.2：导出、性能与发布验收

**修改：** `crates/notebook/src/import.rs`、`crates/notebook/src/markdown.rs`、`docs/使用指南.md`、`docs/架构与数据格式.md`；更新当天记录和项目验证报告。

1. 增加 Markdown 大纲和文档预览引用的导出测试；可读导出明确不保证图结构无损往返，结构化备份才是完整迁移途径。
2. 对阶段 0 的性能样本和 Git 体积试验复测：记录 `.git` 在不同提交数、预览和附件下的实际增长；断言打开预览不增加仓库文件或产生内容修改。
3. 在桌面与窄屏执行创建、编辑、预览、同步、历史、备份恢复、断网、回收站和失败恢复的端到端验收；运行 `npm run check`、`npm test`、`cargo test -p notebook-core`，以及项目现有对应 e2e 脚本。
4. 更新使用指南说明旧客户端风险、预览限制、离线及同步行为；记录所有未通过项目和设备范围。仅当数据安全、备份与预览验收全部通过时标记首版完成。
