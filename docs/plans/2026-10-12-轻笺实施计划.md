# 轻笺实施计划

**目标：** 使用同一套代码构建桌面、安卓和苹果移动端笔记工具，支持多个 Git 仓库与 Notion 数据导入。

**架构：** 网页模块提供共同的中文工作台、块编辑器和数据库视图；Rust 核心负责文件、导入、版本控制与同步；Tauri 2 提供统一应用入口和系统文件接口。移动端原生编译与构建只在 GitHub 流水线执行。

**技术选型：** Rust、Tauri 2、原生网页模块、内嵌 Git 库、结构化文本文件与内容摘要附件。

## 实施步骤

1. 建立中文协作约定、每日追加记录和测试驱动流程。
2. 为存储、页面层级、回收站、版本冲突和工作区隔离编写失败测试，完成原子保存。
3. 为 Notion 压缩包、子页面、内部链接、附件、表格、备份恢复和不安全路径编写失败测试，完成导入报告。
4. 使用真实临时仓库验证提交、推送、克隆、分叉保护、版本恢复和远程格式验证。
5. 完成统一应用入口与只监听本机的开发服务；平台差异仅保留系统接口。
6. 完成中文工作台、页面树、搜索、块编辑、模板、关联、目录、回收站和版本历史。
7. 完成数据库表格、看板、列表，以及筛选、排序、记录与属性编辑。
8. 完成仓库管理、主题、国际化、磁盘统计、原生导入导出和响应式布局。
9. 执行独立代码审查；逐项增加回归测试，修复存储和迁移的边界问题。
10. 执行核心测试、前端测试、完整界面验证及当前桌面构建；移动端仅准备云端流水线，不在本机编译。
11. 补齐中文使用说明、数据格式、发布要求、验证报告和后续范围，并追加每日记录。

## 设计约定

系统中文字体、浅灰导航、白色正文、靛蓝选中态、青绿本地状态。工作台突出真实笔记内容，侧栏展示工作区及磁盘用量。手机使用同一界面和编辑数据，提供导航抽屉与按钮排序。

## 验收边界

- 保存成功后的笔记能够重新读取，失败不覆盖已有文件。
- 多工作区文件与历史隔离，离线仍可写作。
- Git 同步不强推、不重置分叉内容，远程数据验证通过后才更新当前页面。
- 导入不执行脚本、不写出工作区之外、不静默丢失受支持附件。
- 每天只追加同一份中文记录，文件名包含日期、时间和主题。
- 同一份界面与 Rust 核心覆盖五个平台；移动端实际编译通过情况以未来云端执行结果为准。
- 本次交付为可运行首版，不宣称已经完整复刻 Notion 的协作、权限、公式和关联汇总。
